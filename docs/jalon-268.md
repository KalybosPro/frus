# Jalon 268 — `frus` facade crate: **a single dependency**

## The goal

To extend the single entry point (milestone 267) to a complete one-line setup: an app depends on only
**one** crate, `frus`, and writes `frus::main!(App::default())`. Before, it had to list `frus-shell`
**and** `frus-widgets` (and know how they were split).

## The facade

- **`crates/frus`** (a new crate) — containing **nothing but re-exports**:
  - `pub use frus_widgets::*;` — the widgets, the theme, the layout, and the DSL;
  - `pub use frus_shell::{Application, Command, Lifecycle, Subscription};` — the framework layer;
  - `pub use frus_shell::{anyhow, log};` — for the thin binary and the macro (the app does not declare
    those crates);
  - `pub use frus_shell::main;` and `pub use frus_widgets::{column, row};` — the **macros**, named
    explicitly because a glob does not re-export `#[macro_export]`s. Hence `frus::main!`,
    `frus::column!`, `frus::row!`.

## The subtle point: `$crate` crosses the facade

`main!` is defined in `frus-shell` and its body uses `$crate::run`, `$crate::AndroidApp`, and so on.
`$crate` **always** designates the defining crate (`frus-shell`), even when invoked as `frus::main!`
from an app that depends **only** on `frus`. Rust resolves `$crate` **transitively** (through the
dependency graph): `frus-shell` is present there by way of `frus`, so the expansion (`frus_shell::run`,
…) compiles without the app naming `frus-shell`. Verified: `frus-hello` built through the facade
compiles on desktop **and** produces a working `android_main`.

## Adoption

- **`frus-hello`** (the canonical example) and the **`templates/app` template**: a single `frus`
  dependency, `use frus::{…}` imports, a `frus::main!(…)` entry, a
  `fn main() -> frus::anyhow::Result<()> { <crate>::run() }` binary. (The `wasm32`-targeted
  `wasm-bindgen` dependency stays — the Web entry refers to it.)
- **Internals not migrated**: `frus-demo` and `frus-transforms` keep the direct crates +
  `frus_shell::main!` (they touch `frus-widgets` internals; the facade targets **the developer's app**,
  whose showcase is the template).

## Verification

- **Desktop**: `frus` (the facade) and `frus-hello` compile; `frus-hello`'s 2 tests green; the rest of
  the workspace unchanged.
- **Android**: the `frus-hello` APK built through the facade (the `android_main` generated by
  `frus::main!` assembles into the `.so`).
